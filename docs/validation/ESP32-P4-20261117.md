# PortScope ESP32-P4 实机验收记录

日期：2026-11-17。结论：本机目标链路验收通过，原固件已恢复，恢复后整片 32 MB Flash digest 校验通过。

## 被测版本与硬件

- 仓库 main 基线：`64ff509`，包含本地 #7 最终整合修复（导入范围验证及跟随系统主题绘图颜色）。
- 被测 `index.html` SHA256：`6e346caed36eb3cf3fad7ca86c13d4a2188abae4b6f8253adb8a373b20c86b6c`。
- ESP32-P4 v3.2，MAC `80:f1:b2:d7:26:fc`；COM28 为板载 CH343 下载／控制台，COM29 为外接 CH340。
- 物理链路：GPIO2/TX → CH340 RX，GPIO3/RX ← CH340 TX；沿用用户在关联会话中确认并通过测试的当前接线。
- 串口参数：9600 baud、8N1、无硬件流控，板端内部回环明确禁用。
- 浏览器：本机 Windows Chrome，localhost 页面，原生 `navigator.serial`、`SerialPort` 及 reader／writer；没有替换串口 API、端口或收发对象。
- 自动验收使用隔离的 Chrome 测试配置预授权 COM29，调用应用既有端口连接管线。首次授权选择器的人工操作不在本次自动验收范围内；日常浏览器及系统策略未修改。

## 实测结果

| 项目 | 结果与证据 |
| --- | --- |
| 浏览器实际收发与界面断言 | 113 项通过 |
| SUM8、XOR8、LRC8、CRC-16/MODBUS | 每种 10 次正常往返，共 40 次；板端独立计算校验后才响应 |
| 参数输入、组帧、预览、发送 | 实际按钮事件进入原发送管线，预览与发送日志字节逐帧相同；板端解析并变换参数回传，排除短接回显 |
| 命名字段与显示 | UInt16 序号、Int16、Float32、UInt16 大端重读、bit0／bit7 正确；实际数值框更新 |
| 编码与设备处理示例 | Int16 -1234 下发后返回 1234；Float32 1.5 下发后返回 2.0；flags 0x5A 返回 0xFF |
| 发送校验负例 | 每种算法发送一个故意损坏的校验，板端独立日志共拒绝 4 条 |
| 接收校验负例 | 每种算法让板端返回坏校验，原有有效数值和曲线样本不被覆盖 |
| 分包与显示空闲边界 | 板端先发送 5 bytes，间隔 250 ms 再发送余下字节；半帧不更新值，完整后正确解析 |
| 连续三帧 | 板端一次写入三帧，序号及数值分别正确 |
| 全局组件布局 | 实机使用三列指令框、数值框和时域图；1／2／3 列及 FFT／柱状图的完整布局覆盖见既有浏览器回归 |
| 设备 JSON | 实际保存文件、文件输入打开；串口参数、协议、校验、间隔、字段、组件及手动视图恢复，关闭真实串口并停止发送任务、归档有真实报文的录制，不自动重连或发送 |
| JSON 恢复后的实收实发 | 显式重连后，恢复的指令及接收解析继续通过 |
| 手动波形 | 真实接收继续，手动时间参考冻结；AUTO 回到实时跟随 |
| 9600 baud 空闲分行 | 板端发送无换行的 `IDLE_A`，间隔 300 ms 再发 `IDLE_B`；监视器为两行，原始接收仍严格为 `IDLE_AIDLE_B` |
| 最终端口状态 | 浏览器 reader／writer 正常释放并关闭，临时浏览器退出 |

板端独立控制台确认共接收 **55 条有效命令**（四种算法分别为 13／13／13／16），另拒绝 **4 条错误校验命令**。CRC 实机采用 MODBUS 低字节先；高字节先及其他整数边界继续由已通过的独立浏览器向量测试覆盖，不将其描述为本轮硬件验证。

## 实际报文示例

SUM8 首帧发送：

```text
A5 5A 00 01 01 00 2E FB 00 00 C0 3F 5A 00 83 00 0D 0A
```

设备回传：

```text
5A A5 00 01 01 00 D2 04 00 00 00 40 FF 00 16 00 0D 0A
```

CRC-16/MODBUS 首帧发送／回传：

```text
TX A5 5A 03 01 2D 01 2E FB 00 00 C0 3F 5A 00 B4 F1 0D 0A
RX 5A A5 03 01 2D 01 D2 04 00 00 00 40 FF 00 69 66 0D 0A
```

## 固件保护与恢复

- 使用已有完整 32 MB 原固件备份，SHA256：`c2d4ac0f25246b053d4d25f62580578a5f2b2a37002f7cda7a9d3a548702fde0`。
- 写入前先校验当前整片 Flash 与备份 digest 一致，同时核对芯片 MAC；不匹配则不烧录。
- 临时应用 `portscope_acceptance.bin` 为 233984 bytes；镜像偏移、大小、SHA256 记录于 flash-plan.json。
- 测试结束写回覆盖全部可能改写扇区的原始前缀（303104 bytes），再对整片 33554432 bytes 执行 verify_flash，结果 `verify OK (digest matched)`，随后 hard reset。
- 没有修改 eFuse，未修改用户的原备份，未将临时验收固件留在开发板中。

## 本地证据与范围

完整产物在本工作区 `artifacts/hardware-acceptance/`：

- `acceptance-desktop.png`：测试结束后的浏览器界面。

本结论针对当前 Windows／Chrome、该开发板及当前接线。不是其他电脑、浏览器、固件协议或全部数值类型的实体设备兼容性声明；既有 release 快照尚未更新。
