## 快速上手（3 步）

1. **连接**：打开页面 → 左侧「设备连接管理」→ 点击「连接设备」，在浏览器弹出的窗口里选择你的串口
2. **确认数据**：设置波特率 / 数据位 / 停止位 / 校验位 → 切到「**监视**」，确认设备正在输出数据
3. **留存实验**：点击顶部 **REC** 开始录制时间线 → 切到「**解析**」建立解析规则、添加图形

> **最值得记住的一条：先录制时间线，再做解析。**
> 解析规则可以反复修改、重新套用；而原始数据只会出现一次。

## 功能一览

| 模块 | 能做什么 |
| --- | --- |
| **设备连接管理** | 串口连接 / 断开、自动重连、波特率预设、数据位 / 停止位 / 校验位、硬件流控、DTR / RTS / BREAK 控制、CTS / DSR / DCD / RI 状态、失焦自动断连 |

| **时间线** | 录制 / 回放 / 冻结锁定 / 导入导出（`BIN` `TXT` `CSV`），回放时重新生成监视器内容、解析结果与图形 |
| **导出** | 原始时间线（`BIN` / `TXT` / `CSV`）与解析结果（`TXT` / `CSV`，带 UTF-8 BOM，Excel 可直接打开） |
| **主题与布局** | 跟随系统或手动切换浅色 / 深色；宽屏与窄屏自动适配 |

## 典型使用流程

```mermaid
flowchart LR
  A["连接设备"] --> B["监视原始数据"]
  B --> C["REC 录制时间线"]
  C --> D["建立解析规则<br/>文本模板 / HEX 结构表"]
  D --> E["时域图 / 频域图 / 柱状图"]
  E --> F["导出<br/>原始时间线 或 解析结果"]
```

这条流程的核心价值：

- **原始数据始终保留** —— 时间线保存的是「实验现场」，不是「实验截图」
- **解析规则可反复调整** —— 换模板、换字段后可以重新套用同一份原始数据
- **图形与解析结果同源** —— 都建立在同一个「成功帧序列」上
- **结果能带走** —— 导出为标准 `CSV` / `TXT`，直接进入 Excel / Python / MATLAB / Origin

## 详细说明

### 1. 设备连接管理

系统的配置中枢。宽屏下以左侧面板展开 / 折叠；窄屏下以浮层打开，内容与逻辑完全一致。

这里设置的项都会影响后续的**录制、解析和回放**行为，建议在实验开始前先确认：

- 串口连接与断开、自动重连、失焦自动断连
- 波特率与预设值、数据位、停止位、校验位
- 硬件流控、DTR / RTS / BREAK、CTS / DSR / DCD / RI
- **字符编码**：`UTF-8`（默认）/ `ASCII` / `Latin-1` / `UTF-16LE`
- **换行符设置**、结尾补换行符
- 十六进制显示 / 发送、时间戳显示方式

### 2. 监视模式

用于回答「设备到底发了什么、系统到底收到了什么」。

- **自动分显示帧**：遇到 `\r\n` / `\r` / `\n` 结束一行（三者都只算**一次**换行）；未收到换行符时，连续数据接续到当前行，接收空闲达到 **100 ms** 后结束当前行。触发发送或单条累计超过 2048 字节 / 字符时也会收尾。空闲分行不向原始数据插入换行字节。
- **顶部状态**：模式状态、TX / RX 统计、FPS；回放模式下这些统计会按回放位置重新计算
- **显示缓存控制**：只保留最近一段有效数据，长时间运行也不会越用越慢

### 3. 发送功能

| 方式 | 适用场景 |
| --- | --- |
| 立即发送 | 手工输入后立刻发送，遵循当前编码 / 换行 / HEX 设置 |
| 定时发送 | 周期轮询、心跳包、采样触发；维护发送队列按固定间隔循环发送 |
| 触发发送 | 简单握手、自动应答；定义「收到什么后自动回复什么」 |
| 预设发送 | 把高频命令整理为固定条目，可附预期响应，用于稳定重复验证 |

### 4. 解析模式

把原始数据转换为**成功解析帧**，再变成结构化结果与图形。

- **文本解析**：模板宽松匹配，`_`、`-`、`.` 都可作为字段名的一部分；支持自动识别稳定结构并提示一键应用模板
- **十六进制解析**：默认结构为 `帧头 A5` + 数据 + `校验 SUM8` + `帧尾 5A`，可自定义帧头 / 帧尾 / 间隔符 / 校验方式
- **实时结果卡片**：每成功识别一帧即进入统一的成功帧序列，最新值以卡片形式展示，便于确认字段是否提取正确

### 5. 时间线系统

不是「顺手录个日志」，而是一套围绕原始数据的记录 / 回放 / 导出体系。

- **记录内容**：带时间信息的**原始串口数据**，因此可以重新用于重建监视器显示、重新套用解析模板与结构表、重新生成时域图与频域图
- **回放**：切换到任意时间线后，系统会重新走一遍数据解释过程，而不是播放一张静态快照
- **冻结**：实时模式下可临时冻结（鼠标悬浮暂停按钮）或锁定冻结（点击），只影响显示层，**后台仍继续接收**
- **导入导出**：`BIN` / `TXT` / `CSV`；录制得到的时间线也可直接导出为 `TXT` / `CSV` 继续处理

### 6. 导出与数据格式

| 导出内容 | 格式 | 用途 |
| --- | --- | --- |
| 原始时间线 | `BIN` / `TXT` / `CSV` | 保存实验现场、分享测试过程、原始数据归档 |
| 解析结果 | `TXT` / `CSV` | 已按模板 / 结构表解释后的字段数据，直接交给 Excel、Python、MATLAB、Origin |

> 导出 `CSV` 时写入 **UTF-8 BOM**，Excel 双击打开不会中文乱码（v2.0 起）。

### 7. 配置复用

开发版本新增 **设备 JSON 保存／打开**：解析页或右上角菜单选择“保存 JSON”，可在本地备份当前设备配置；选择“打开 JSON”恢复。文件使用 UTF-8，包含串口参数、现有收发规则、解析结构、图表绑定及布局，不包含日志、录制数据或发送任务运行状态。

打开时先校验文件；无效文件不改变当前配置和连接。有效文件打开前停止发送、归档正在进行的录制并断开旧连接，随后恢复配置，等待手动连接和启用发送。配置可保留自动重连偏好，但本次打开及之后重新加载页面都不会自行连接，直到用户手动发起连接。

二进制结构表的间隔区域现在可填写跳过的 **n bytes**（正整数，单行及整帧最多 65536 bytes）。每行显示从 0 起算的字节偏移，整帧长度由各行实际长度自动计算，包含帧头、数据、间隔、校验和帧尾。新建间隔区域只跳过字节；旧配置已有的固定 HEX 匹配保持原行为。

新文件格式标识为 `PortScopeDeviceConfig`、版本 `1`；也支持打开原 `SerialWebUserConfig` 版本 `1` 的完整配置。独立协议、指令和布局不另设文件格式。收发校验、全局组件列数、固定偏移字段、数值框、参数化指令框及波形显示范围已接入同一设备 JSON。

### 参数化指令框（开发版本）

1. 在解析页点击“指令框”，通过设置修改标题、添加多个指令按钮；展开各按钮的“编辑”配置。
2. 填写按钮名称和 HEX 字节模板，模板中须预留参数及校验的空间。每个按钮独立设置追加换行和共享校验规则，不受手动发送区的全局校验／换行设置影响。
3. 添加参数，设置名称、从整帧 0 起算的模板偏移、Int／UInt 8、16、32 位或 Float32，以及多字节大小端。可设置默认值和允许范围；默认值可留空，使用时必须手工填写。
4. 枚举可填为每行 `名称=数值`，例如 `停止=0`、`运行=1`；使用时显示下拉选项。留空时显示数值输入框。
5. 修改参数后自动生成最终 HEX 预览：先写入模板、追加本按钮配置的换行，再调用共享校验计算并覆盖校验字节。参数重叠、越界、溢出或输入不合法时显示具体原因并禁用发送。

例如模板 `AA 00 00 00`，在偏移 1 放置小端 UInt16 参数 500，SUM8 计算偏移 0／长度 3／校验位置 3，最终报文为 `AA F4 01 9F`；参数改为 100 时变为 `AA 64 00 0E`。

未连接时按钮禁用并提示手动连接。发送时按当前输入重新组帧，通过现有串口写入、日志和统计管线发送；写入期间禁用当前按钮及参数编辑，避免重复提交。结果只表示“已发送”或“发送失败”，不表示设备执行成功；设备状态通过独立上报字段观察。不新增应答匹配、超时、重试、比例换算或脚本。

指令框在 `charts` 数组中使用 `chartType: "command"`，`commands` 保存模板、换行、校验及参数定义；参数的默认值、最小值、最大值使用数值文本，范围留空表示不额外限制，枚举使用上述多行文本。当前输入、发送结果及运行状态不写入设备 JSON。打开文件恢复规则和默认值，仍不自动连接或发送；现有固定指令和预设发送继续可用。

验证入口为 `python tools/test-command-panels.py`（Windows Chrome、Python `websockets`），覆盖独立编码向量、共享校验、交互编辑、模拟串口成功／失败、JSON 往返及与数值／曲线组件的共同布局。

### 固定偏移字段与数值框（开发版本）

1. 在十六进制结构表中设置完整帧结构；若载荷只需要按偏移取值，可用 n 字节间隔区域表示载荷长度。已有数据行及旧 SUM8 规则继续兼容。
2. 在“固定偏移字段”中新增字段，填写名称、字节偏移、类型和多字节字节序。偏移从整帧第 0 字节起算，包含帧头；多字节类型从该位置读取连续字节，允许多个命名字段重叠读取。
3. 支持 Int8／UInt8、Int16／UInt16、Int32／UInt32、Float32，以及 bit0～bit7。bit 从指定字节提取，bit0 为 LSB、bit7 为 MSB，显示数值 0／1。字段名不能重复，也不能覆盖已有结构表字段；偏移和读取长度不得超出整帧。
4. 点击“数值框”，在设置中选择字段并填写标题。一个框可显示多个字段，同一字段可绑定到多个框和曲线，所有组件使用协议统一解码的结果。

尚无有效帧时显示“等待”；完整帧通过启用的校验后才更新。分包等待完整帧，粘包逐帧处理；校验失败或字段越界不会写入错误状态，原始监视、录制和导出字节保留。只显示字段名与值，不增加开／关映射、比例换算或告警。

字段保存在 `parser.binary.fields`，每项包含 `name`、`offset`、`dataType`、`byteOrder`（`le`／`be`）。数值框作为 `chartType: "numeric"` 的组件保存于现有 `charts` 数组，绑定存于 `channels.bindings`；顺序、标题和全局列数使用同一设备 JSON。本地打开后仍要求手动连接和启用发送，旧文件缺少字段表时按空表兼容。

验证入口：`python tools/test-fixed-fields.py`（Windows Chrome、Python `websockets`），覆盖独立字节向量、真实接收管线、多组件绑定、坏帧隔离、字段编辑及配置往返，截图和结果输出到 `artifacts/`。

### 波形视图（开发版本）

时域图和频域图下方提供 **X＋／X－、Y＋／Y－**，分别缩放横轴和当前纵轴；图内拖动平移，坐标轴区域拖动或滚轮只缩放对应轴。图框设置内可输入 X／Y 最小值和最大值，点击“应用范围”；空值、非有限数值、反向或跨度小于 `1e-9` 的范围会拒绝应用。差异量程下，纵轴操作作用于所选通道，选择“全部通道”则一起调整。

时域图的横轴刻度为秒，范围输入使用**相对冻结时刻的毫秒**；频域图横轴使用 Hz，纵轴显示原始幅值，不额外推断物理单位。手动查看时冻结时域图的时间参考，继续接收数据；点击“恢复自动／实时跟随”回到最近 10 秒及自动纵轴量程。频域图恢复按钮回到自动量程。所有图表使用与主刻度对齐的虚线网格，主题与容器尺寸变化后重绘。

范围、缩放、平移和通道选择随设备 JSON／本地偏好保存；不保存运行时冻结时间戳、采样或日志。重新打开配置后，手动范围以本次数据的时间参考恢复，不自动连接或发送。列数始终由用户选择，不增加游标、触发捕获或测量统计。

验证入口：`python tools/test-waveform-view.py`（Windows Chrome、Python `websockets`），覆盖独立缩放、拖动、非法范围、多通道量程、网格坐标、主题、列数、实时恢复及 JSON 往返，结果与截图位于 `artifacts/`。

### 全局组件列数（开发版本）

解析页“添加图框”旁可选择 **1／2／3 列**，时域图、频域图和柱状图统一等宽、按既有顺序逐行排列；末行不足时仍保持列宽。沿用现有顺序按钮，不新增拖拽、跨列和自由摆放。数值框、指令框也使用同一组件容器。

本次仅面向 Windows 桌面使用，不新增手机或平板适配。列数始终由用户决定，窗口缩小或侧栏占用空间都不会自动改为单列，允许图框被压缩。切换列数、增删图框、改变窗口宽度或收起侧栏后，画布按实际容器宽度重绘，保留字段绑定、手动视图及采样数据。

列数保存在设备 JSON 的 `layout.componentColumns` 和本地偏好中，仅允许整数 `1`、`2`、`3`；旧文件缺少此项时恢复为单列。图框顺序继续使用配置中的组件数组顺序。

布局浏览器回归入口为 `python tools/test-component-columns.py`，需要本机 Chrome 和 Python `websockets` 包；测试只在本机控制无头浏览器，产物输出到 `artifacts/`，网页应用本身没有新增依赖。

### 收发协议校验（开发版本）

- 支持 SUM8（字节和取低 8 位）、XOR8（逐字节异或）、LRC8（字节和的二补码）与 CRC-16/MODBUS；CRC 默认低字节先，可改为高字节先。CRC 参数为多项式 `0x8005`（反射计算 `0xA001`）、初值 `0xFFFF`、无最终异或，参照 [Modbus 官方串行协议规范附录 B](https://www.modbus.org/file/secure/modbusoverserial.pdf)。
- 发送区展开“发送校验”，设置算法、计算起始偏移、计算长度及校验位置。坐标基于编码并追加换行后的最终字节帧，从 0 起算、包含帧头。内容中须预留 1 byte（CRC 为 2 bytes），计算后覆盖；范围不得与校验字段重叠，也不得超出整帧。关闭校验时保留原输入。
- 手动、定时、触发及预设发送共用这一配置和计算路径；发送区显示当前输入的最终 HEX 预览。例：HEX 内容 `01 03 00 00 00 0A 00 00`，关闭追加换行，CRC-16/MODBUS、起始 0、长度 6、校验位置 6、低字节先，得到 `01 03 00 00 00 0A C5 CD`。
- 接收时在二进制结构表的校验行设置算法、起始偏移和长度；校验位置由行顺序决定。关闭接收校验仍保留字段的 1/2 字节宽度。只有完整协议帧参与校验，监视页的 100 ms 空闲分行不作为协议边界。
- 校验失败显示实际值和期望值，整帧不更新解析值、图表和最新有效状态，原始监视与录制数据保留。旧配置保留“SUM8（旧数据行范围）”，仅累计校验行之前的数据行，跳过帧头、间隔和帧尾。
- 配置存于 `settings.txChecksum` 和 `parser.binary.rows[].checksum`，包含 `enabled`、`algorithm`、`start`、`length`、`byteOrder`；发送另含 `offset`，旧接收范围用 `legacy: true` 标识。算法值为 `sum8`、`xor8`、`lrc8`、`crc16-modbus`；`enabled: false` 表示关闭。打开旧文件不会自动启用发送校验。

菜单中的「**复制配置** / **粘贴导入** / **清空配置**」可以整体搬运：

- 串口参数、发送配置、解析模板、图框结构与图形设置

适合团队统一协议模板、保存成熟实验配置、换机或换人时快速复现同一套实验环境。

## 常见问题

**Q：点「连接设备」没有反应 / 不弹出串口选择框？**
A：依次确认：① 用的是 Chrome / Edge；② 页面在 `HTTPS` 或 `localhost` 下打开（`http://` 的普通域名不行）；③ 页面上是否出现「不支持 Web Serial API」提示。

**Q：显示乱码怎么办？**
A：先检查「设备连接管理 → 字符编码」。默认 `UTF-8`；如果下位机发的是纯 ASCII 或单字节数据，可试 `ASCII` / `Latin-1`；单片机用 2 字节宽字符的试 `UTF-16LE`。**浏览器不支持 GBK / GB2312**，遇到中文建议让下位机改发 `UTF-8`。

**Q：接收区为什么会出现空行，或者该有空行却没有？**
A：空行完全由**换行符**决定，当前的判定逻辑如下：

1. 遇到 `\r\n`、`\r`、`\n` 即结束当前行 —— 三者都只算**一次**换行，`\r\n` 不会被当成两次（所以不会凭空多出一行）
2. 如果 `\r` 与 `\n` 恰好落在两次接收之间，会被识别为**同一个换行**
3. 设备如果**连续发送多个换行**（如 `\n\n`、`\r\n\r\n`），中间就会显示为真正的空行 —— 这是设备端本来就发出的空行，不是上位机多算的
4. 设备**一直不换行**时，数据会接续到当前这一条，直到：接收空闲达到 100 ms / 出现换行符 / 你触发一次发送 / 单条累计超过 2048 字节（或 2048 字符）被强制断开
5. 空闲阈值按 9600 波特率保守取 **100 ms**（8N1 下约 96 个字节时间），每次接收重新计时；不完整的多字节字符会等待续字节。文本和 HEX 监视均适用，原始录制和导出字节保持不变。

所以：看到多余空行（或少空行）时，先切到**十六进制视图**确认设备实际发出的字节 —— 如果设备端确实连发了多个换行，那就是真实内容。

**Q：数据量很大时会卡吗？**
A：**会。** 受实现方式限制（网页单页面实时渲染），高速或长时间的数据流会明显卡顿，这是网页端方案的固有上限。如果你的目标是高速数据采集与处理，建议不要用网页端承载：可以让**硬件自身带时间戳**后本地记录/导出、采用**定制方案**，或改用**本地 Python 脚本**直接读串口并落盘。网页端更适合看现象、调协议，以及中小数据量的观察与轻量记录。

**Q：需要额外安装、部署或准备其他文件吗？**
A：不需要。**单个 `index.html` 就能完成所有事情** —— 界面、样式、逻辑、图标全部内联，不依赖任何外部 CSS / JS / 图片，也不需要后端服务。放到任意静态托管，或直接双击本地打开，功能就是完整的。

**Q：在线版和离线版有什么区别？**
A：功能一致。在线版始终是最新版；离线版是你下载到本地的单个 HTML 文件，不自动更新，适合无网络或需要固定版本的场景。
